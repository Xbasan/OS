## Практическое занятие № 9. Мониторинг использования памяти

**Цель работы:** Освоить основные утилиты и методы мониторинга оперативной памяти и виртуальной памяти (Swap / Файл подкачки), научиться выявлять утечки памяти и анализировать задействованные системные ресурсы.

**Оборудование и ПО:** Операционная система семейства Linux (Ubuntu, Debian, CentOS, WSL) или эмулятор terminal/PowerShell для Windows.

---

### Задание 1. Базовый анализ оперативной памяти (CLI)

1. Откройте терминал Linux (или WSL / эмулятор).
2. Выполните команду `free -h` и разберите её вывод:
* Каков общий объём оперативной памяти (`total`)?
* Сколько памяти используется (`used`), зарезервировано под кэш/буферы (`buff/cache`) и доступно для запуска новых процессов (`available`)?
* В чём разница между показателями `free` и `available`?


3. Запустите команду `vmstat 2 5` (вывод 5 отчётов с интервалом в 2 секунды):
* Объясните значение колонок `swpd`, `free`, `buff`, `cache`, `si` (swap-in) и `so` (swap-out).
* Определите, происходит ли в данный момент активный обмен данными с разделом подкачки.

### Задание 2. Анализ потребления памяти процессами

1. С помощью команды `ps` выведите ТОП-10 процессов, потребляющих больше всего оперативной памяти:
```bash
ps aux --sort=-%mem | head -n 11

```


2. Разберите разницу между `VSZ` (Virtual Memory Size) и `RSS` (Resident Set Size) для первых двух процессов из списка:
* Почему объём виртуальной памяти (`VSZ`) часто значительно превышает объём фактически занятой физической памяти (`RSS`)?


3. Запустите интерактивный утилитарный монитор `htop` (или `top`):
* Отсортируйте список процессов по использованию памяти (клавиша `F6` в htop или `Shift + M` в top).
* Найдите процесс с максимальным значением `RSS` и запишите его PID, команду и процент использования памяти (`%MEM`).

### Задание 3. Симуляция нагрузки и анализ подкачки (Swap)

> **Внимание:** Выполняйте задание в изолированной/тестовой среде.

1. В отдельном окне терминала запустите мониторинг с помощью `vmstat 1` или `htop`.
2. Смоделируйте временное повышение нагрузки на оперативную память, используя один из вариантов:
* **Вариант А** (с помощью `stress` / `stress-ng`):
```bash
stress --vm 1 --vm-bytes 80% --timeout 30s

```


* **Вариант Б** (без установки сторонних утилит — через Python):
```bash
python3 -c 'a = "A" * (1024 * 1024 * 500); input("Нажмите Enter для выхода...")'

```




3. Проследите изменения в метриках:
* Как изменились показатели `used`, `free` и `available`?
* Наблюдается ли рост показателей `si` / `so` в `vmstat`?
* Что происходит с памятью после завершения процесса нагрузки?

### Задание 4. Выявление утечек памяти и анализ карт памяти процессов

1. Выберите любой работающий процесс (например, ваш веб-браузер, bash-сессию или системный сервис) и узнайте его `PID`.
2. Изучите карту памяти выбранного процесса через виртуальную файловую систему `/proc`:
```bash
cat /proc/<PID>/status | grep -iE 'vmsize|vmrss|vmswap'

```


3. Для детального анализа динамически выделяемой памяти (стек, куча/heap, разделяемые библиотеки) выполните:
```bash
pmap -x <PID> | tail -n 20

```


4. Ответьте на вопрос: какие библиотеки или сегменты занимают наибольший объём в адресации данного процесса?

### Задание 5. Дополнительное/Творческое задание (среда Windows / PowerShell)

1. Откройте **Диспетчер задач** (Task Manager) $\rightarrow$ вкладка **«Производительность»** $\rightarrow$ **«Память»**.
2. Запустите **Монитор ресурсов** (`resmon`) и объясните значение категорий памяти:
* *Зарезервировано аппаратурой*;
* *Используется*;
* *Измененная*;
* *Ожидание*;
* *Свободно*.


3. Откройте консоль PowerShell и выполните команду для получения ТОП-5 процессов по рабочей области памяти (Working Set):
```powershell
Get-Process | Sort-Object WorkingSet64 -Descending | Select-Object -First 5 Name, WorkingSet64, VirtualMemorySize64

```
